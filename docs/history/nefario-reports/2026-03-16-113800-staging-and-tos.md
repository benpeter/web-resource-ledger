## Key Design Decisions

1. **No Worker endpoints for legal docs**: GitHub serves Markdown with caching and
   versioning. Three discovery mechanisms (Link header, health endpoint, OpenAPI spec)
   provide adequate API coverage. Helix Manifesto lean-and-mean principle.
2. **Documents at repo root**: TERMS.md and CONTENT-POLICY.md follow LICENSE/SECURITY.md
   convention. No legal/ subdirectory.
3. **Inlined test steps**: Dropped ci.yml workflow_call reuse after lucy flagged
   BASE_REF breakage. Inlined npm ci/test/lint in deploy-staging.yml.
4. **Email for abuse reporting**: Zero attack surface, KISS, matches project scale.
5. **Accept failed captures in smoke test**: Validates infrastructure, not page
   renderability. test-minion and margo consensus.
6. **Link header on every response**: Added to universal header block, not conditionally
   on authenticated endpoints only. Simpler, no conditional logic.

## Decisions

### D1: Worker endpoints vs GitHub-hosted documents
Sided with api-design-minion. No Worker endpoints. Helix Manifesto lean-and-mean.
GitHub serves with better caching and versioning. Three discovery mechanisms provide
adequate coverage. Rejected: software-docs-minion's self-contained API argument.

### D2: ci.yml reuse vs inlined steps
Sided with margo + lucy. Inlined test steps. workflow_call would break ci.yml's
change detection. 10 lines of YAML saved is not worth event-context coupling.

### D3: Footer link color hierarchy
Sided with ux-strategy-minion over margo. 3 lines of CSS for improved abuse link
scannability. Negligible complexity for meaningful UX improvement.
