## Summary

Per-tenant usage metering for WRL. D1 `usage_counters` table with composite PK `(tenant_id, period)` tracks capture count, storage bytes, and API call count per calendar month (UTC). Counters increment via atomic D1 UPSERT on capture completion (queue consumer) and authenticated API calls (3 handlers). All increments deferred via `ctx.waitUntil()` -- zero latency impact on the hot path. Admin endpoint `GET /v1/admin/usage?tenant={id}&period=YYYY-MM` exposes usage data with existing admin auth. 7 files modified, 3 created, +830 lines. 791 tests pass (36 new).

## Original Prompt

GitHub Issue #101: R25 -- Usage Metering

Per-tenant usage counters maintained in D1, tracking captures, storage consumption, and API calls. An admin endpoint exposes usage data for billing and quota enforcement.

Success criteria: D1 per-tenant counters (capture count, storage bytes, API calls), counters increment on capture stored and API request authenticated, admin usage endpoint with period filtering, calendar month billing periods (UTC), eventually consistent (deferred writes), persisted in D1, monotonically increasing within period.

## Key Design Decisions

1. **Single-table UPSERT over multi-table normalization** -- Composite PK `(tenant_id, period)` with `INSERT ... ON CONFLICT DO UPDATE SET col = col + excluded.col`. One table, one atomic SQL statement per increment. No joins, no aggregation at query time.

2. **waitUntil for all counter increments** -- Defers D1 writes to after response. Catch-and-warn pattern means failed increments never break captures or API responses. In-memory batching rejected because Worker restarts would lose data.

3. **Only 3 handlers get API call counting** -- Lucy caught that synthesis listed "6 authenticated handlers" but only 3 use tenant auth (verifyApiKey). Admin operations (verifyAdminKey) don't count toward tenant usage.

4. **TextEncoder for consistent byte counting** -- UTF-8 `byteLength` for both HTML and headers JSON. Matches what R2 stores. Code review caught inconsistent String.length usage.

5. **computePeriod() as pure function** -- `date.toISOString().slice(0, 7)` ensures UTC everywhere. Injectable date parameter enables deterministic testing.
