## Original Prompt

Eliminate silent catch blocks — fail loudly on unexpected errors. All `catch` blocks in the codebase either log the error or handle a specific, named error type. Silent error swallowing is eliminated. Degraded features report distinct status values so operators can distinguish "service unavailable" from "misconfigured."

## Key Design Decisions

1. **console.warn over console.error for log.js meta-failures** — Telemetry degradation is not a system failure. The `wrl:` prefix ensures filterability regardless of severity.

2. **console.warn only (no Coralogix) for signing.js and ip-hash.js catch blocks** — signing.js fires once at key import time. ip-hash.js is on every request — adding `log()` would add a network call in the hot path.

3. **signing.key_unavailable Coralogix events at call sites** — Added at `handleVerifyCapture` and `handleGetSigningKey` in index.js where `env` and `ctx` are available. Distinguishes `key_absent` from `key_invalid`.

4. **cdxj.js logs scheme+length only, not raw URL** — URL is attacker-influenced (subresource paths from captured pages). Security-minion flagged this during Phase 3.5 review.

5. **consent.js frame-level catches left intentionally silent** — Cross-origin/detached frame failures are expected browser lifecycle events. All three specialists agreed logging would generate noise proportional to iframe count per page.
