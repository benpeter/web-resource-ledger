## Summary

Integrated RFC 3161 timestamping into the WACZ signing pipeline. Every capture now includes an independent timestamp from DigiCert's TSA when configured. The `datapackage-digest.json` format evolves from v0.1.0 (flat `signedData`) to v0.2.0 (with `signatures` array). Verification validates both the Ed25519 self-signature and the TSA timestamp via a new 4th check. A hand-rolled DER codec (545 lines, zero dependencies) handles TimeStampReq/TimeStampResp encoding/parsing. Graceful degradation ensures captures succeed without timestamps when the TSA is unreachable.

## Original Prompt

Every WACZ bundle includes an RFC 3161 timestamp response from an independent TSA, transforming WRL's evidence claims from operator-asserted to third-party-verified. Verification confirms both signature integrity AND temporal proof.

Success criteria: TSA integration, signatures array extension, dual verification, verification page display, ASN.1 handling, graceful degradation, comprehensive tests.

## Key Design Decisions

1. **DigiCert TSA** (`https://timestamp.digicert.com`) -- universally trusted root CA, no client certs, 50-200ms latency
2. **Hand-rolled DER codec** in `src/rfc3161.js` -- zero new dependencies, matches project's purpose-built module pattern
3. **Certificate chain validation deferred** -- not feasible in Workers, raw token stored for offline verification
4. **4th verification check** (`timestamp`) added to checks array, resolving the api-design vs. UX conflict
5. **Skip tolerance** in verified predicate -- absent timestamps don't fail verification
6. **HTTPS default** for TSA URL per security review
7. **Honest UI copy** -- "Time was recorded by an independent authority (not verified cryptographically)"
